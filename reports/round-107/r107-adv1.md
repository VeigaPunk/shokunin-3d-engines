# r107-adv1 — GATE-ADV1 shard (round 107, 3D side-round)

KEY=GATE-ADV1. Adversary suite extension: r102 found 11 false-pass classes; this seat proposes and
**demonstrates** 6 MORE attack classes against the refreshed (r103/r104-hardened) gate, aimed at
fresh-pin-specific failure modes: wrong-pin acceptance, delta-blindness, card/PROVENANCE
inconsistency.

1. Recover the r102 11 false-pass classes verbatim and re-run each against the live hardened gate —
   establish what is actually closed before claiming anything new.
2. Snapshot the live gate (`corpus/knowledge/unreal-mcp/gate/run_gate.sh`, 442 lines, PIN
   `a6aa73ad`, sha256 `390a25ae…`) into `/var/tmp/r107-gate-adv1/`; never mutate the live tree.
3. Define and demonstrate 6 new classes A–H with a falsifiable acceptance each, plus one CONTROL row.
4. Build `reports/round-107/mutations/adv1-*.sh` — each script applies its mutation to a scratch
   mirror, **confirms the mutation landed**, runs the gate, and prints MISSED / DETECTED with the
   exact exit code. Exit code is captured through a log file, never through a pipeline.
5. Verify every proposed fix by execution (`adv1-verify-fixes.sh`): attack must flip to FAIL while
   the clean tree keeps its pinned numbers. Labels [O]/[I]/[?]; UNPROVEN stays UNPROVEN.

## 2. New attack classes A–H

Full detail, commands and outputs per class: `mutations/adv1-<X>-*.sh` and the captured suite log
`/var/tmp/r107-gate-adv1/logs/SUITE.txt`. Each row below is a demonstrated execution **[O]**.

### CLASS A — wrong-pin acceptance · **MISSED**
Re-vendor `upstream/` from the parent commit `d1b0580` (12 tracked files), regenerate
`audit-reference.sha256` and all 11 seat shards from those bytes, repoint the gate's `PIN` constant
at `d1b0580`; leave `PROVENANCE.md` §1 and `README.md` declaring `a6aa73ad`. Everything the gate can
see is self-consistent — with the wrong commit.

```
gate PIN constant              : PIN=d1b05809e4f089bd0ef174532c692fbcf1562eb7
PROVENANCE.md declares         : a6aa73ada02a9fb1f5415bec491f9942c519b297
MANIFEST_OK=12 … BLOB_DIFFS=0 … CARDS=13 … POINTERS=103 … UNRESOLVED=0
GATE RESULT: PASS (checks failed: 0)   exit=0
```
**Acceptance:** print `PIN_DECLARED=OK` comparing the PIN constant to the pin in PROVENANCE.md;
FAIL when they differ. *Fix verified — §3.*

### CLASS B — delta-blindness · **DETECTED (control row)**
Two flavours: (B1) `GATE_REF` names a clone at `d1b0580`; (B2) `REPO` names a bare remote whose
`main` was force-moved off the pin, run with `GATE_REF` unset so the network path is exercised.

```
B1: GATE_REF=…/ref-old ; CLONE_HEAD=d1b0580… ; GATE RESULT: FAIL  exit=1
B2: no GATE_REF ; REPO=…/bare ; CLONE_HEAD=d1b0580… ; GATE RESULT: FAIL  exit=1
```
CHECK 2 asserts `C2_HEAD = PIN` in both paths, so the gate already closes this. Kept as the suite's
**control**: it is the one row expected non-zero, and it is what proves the harness can observe a
DETECTED result rather than reporting MISSED for everything. My first harness draft read it as
MISSED — because the exit code was being lost through a pipeline, and because B2 still had
`GATE_REF` set and therefore never cloned at all. Both bugs are fixed in `adv1-lib.sh`.

### CLASS C — declared-identity drift · **MISSED**
(C1) `PROVENANCE.md` §1 `pinned commit` cell → `0000…` (4 occurrences rewritten); (C2) `README.md`
declares a 14th card `executability/extra-domain.md` that does not exist, in plain text so no
backtick-pointer pattern sees it.

```
C1: CARDS=13 BAD=0 ; POINTERS=103 UNRESOLVED=0 ; GATE RESULT: PASS  exit=0
C2: planted line present=1 ; cards on disk=13 ; GATE RESULT: PASS  exit=0
```
**Acceptance:** FAIL when the declared pin differs from PIN (same fix as A), and FAIL when README's
card inventory disagrees with `executability/`.

### CLASS D — §2 hash-table drift · **MISSED**
(D1) one per-file sha256 cell in `PROVENANCE.md` §2 → `deadbeef…`; (D2) delete a whole §2 row so the
declared census drops 12 → 11.

```
D1: real upstream/README.md sha256 = 483693ad… ; cell now = deadbeef… ; GATE RESULT: PASS  exit=0
D2: rows left in §2 table = 11 ; files on disk = 12 ; GATE RESULT: PASS  exit=0
```
§2 is a second, independent statement of the same content addresses the manifest carries. After a
fresh pin every one of those 12 values changes, and a transcription error there is exactly the
defect a re-vendor is meant to catch. **Acceptance:** cross-check §2 cells against the manifest and
the row count against `EXPECTED_TRACKED`.

### CLASS E — the manifest SET is not pinned · **MISSED (E1)**
(E1) delete `.manifest.d/seat07.sha256` — 12 → 11 files; (E2) plant a comment-only
`seat99.sha256` — 12 → 13 files.

```
E1: MANIFEST_FILES=11 ; MANIFEST_OK=12 FAILED=0 RC=0 ; GATE RESULT: PASS  exit=0
E2: MANIFEST_FILES=13 ; FAIL per-seat manifest sweep (--strict) failed:
      sha256sum: .manifest.d/seat99.sha256: no properly formatted checksum lines found
    GATE RESULT: FAIL  exit=1
```
`MANIFEST_FILES` is **printed and never compared** (`run_gate.sh:114-115`). E2 is caught, but only
by `--strict`'s *format* rule — not by any set-identity check. This is the r102 F5 class one layer
up: F5 ("seat shards are never verified") was closed with the strict glob; the **set identity** of
that glob was not closed with it. **Acceptance:** FAIL when the count ≠ 12.

### CLASS F — label / evidence incoherence · **MISSED**
(F1) append a live-editor claim to a `static-only` card; (F2) append a second, contradictory
`**Label:** \`verified-here\`` at line 161.

```
F1: planted claim present=1 ; CENSUS static-only=12 unproven-runtime=1 verified-here=0 ; PASS exit=0
F2: second declaration at line 161 ; CENSUS static-only=12 … verified-here=0 ; PASS exit=0
```
`verified-here` is the one label the pinned census forbids, and F2 shows a card can carry it and
still be counted `static-only` (CHECK 3 reads only the first anchored declaration). F1 is this
round's cardinal sin — an unobserved runtime claim riding on a `static-only` card with the census
still reading 12/1/0. **Acceptance:** FAIL on a second label declaration anywhere in a card, and on
a card body asserting a live-editor observation.

### CLASS G — the gate's own spec is unenforced · **MISSED**
`gate/README.md` pins the exact summary lines a green run must print. Rewrite them to values the
gate cannot print (4× `POINTERS=103`→`9999`, 2× `CARDS=13`→`99`, 2× `MANIFEST_OK=12`→`99`):

```
spec sha before e3bc66b7… ; after 9d91b8de…
MANIFEST_OK=12 … CARDS=13 … POINTERS=103 … GATE RESULT: PASS  exit=0
```
A fresh pin re-measures every one of these numbers — r103 already had to issue a `POINTERS=87 → 103`
correction, and the README's own note calls the old value stale. Nothing checks that the contract
and the checker still agree. **Acceptance:** FAIL when the spec's pinned expected values disagree
with what the gate measures.

### CLASS H — an out-of-range line number is never checked for extensionless targets · **MISSED**
Plant `` `upstream/LICENSE:99999` `` in `README.md` (`upstream/LICENSE` has 21 lines). Not a control
sentinel; not a duplicate of r102 F6 (which is about *path* existence, not *line range*).

```
planted line            : See `upstream/LICENSE:99999` for the license.
is a control sentinel?  : NO
pass A regex matches it : NO
pass B strips it to     : upstream/LICENSE (which EXISTS)
POINTERS=104 POINTER_STRINGS=41 SKIPPED_CONTROL_SENTINELS=0 UNRESOLVED=0
GATE RESULT: PASS (checks failed: 0)   exit=0
```
**Mechanism** — the two sweeps are jointly blind to the line number:
- **pass A** (`run_gate.sh:407`) is the *only* range-checking sweep, and its `\.` makes
  `upstream/LICENSE:99999` unmatchable: `printf 'upstream/LICENSE:99999' | grep -ohE "upstream/[^…]+\.[A-Za-z0-9]+:[0-9]+…"` → **no match** **[O]**.
- **pass B** (`run_gate.sh:427`) matches the backtick-wrapped form, but post-processes with
  `tr -d '\`' | sed 's/:[0-9]\+$//'`, i.e. it **discards the line number** before the `[ -e ]`
  existence test. The number is counted (`POINTERS` 103 → 104) and never validated.

Because `reports/round-102/fold-spec.md` A6 falsified exactly this plant and the close note claims
it was fixed (§1), this is a **documented-but-absent check**: `gate/README.md` tells a reviewer it
is closed when it is not.

## 3. Proposed fixes, each verified by execution

`mutations/adv1-verify-fixes.sh` applies each patch to a scratch copy of the gate (never the live
one), re-runs the attack, and re-measures the clean tree. Patch programs are `adv1-patch-*.py`,
kept in separate files so bash never re-parses the inserted shell text — an inline draft wrote a
backtick into the generated script and turned it into command substitution **[O]**.

| fix | clean tree | attack tree |
|---|---|---|
| **H** — pass A `(\.[A-Za-z0-9]+)?` | `POINTERS=103 … PASS` exit 0 | `LINE-OOR … upstream/LICENSE:99999 (max 21)`; `UNRESOLVED=1`; **exit 1** |
| **E** — assert `MANIFEST_COUNT -ne 12` | `MANIFEST_FILES=12 … PASS` exit 0 | `FAIL manifest-file count 11 != pinned 12`; **exit 1** |
| **A/C1** — compare `PIN` to PROVENANCE | `PIN_DECLARED=OK a6aa73ad…`; exit 0 | `FAIL declared pin a6aa73ad… != gate PIN d1b0580…`; **exit 1** |

The A row is the strongest control: on the *identical* class-A tree, the **unpatched** live gate
prints `GATE RESULT: PASS` exit 0 while the patched gate exits 1 **[O]** — the fix is isolated as
the cause. Fixes C2, D, F and G are specified above with a falsifiable acceptance but are **not yet
implemented here**; their acceptance is left for a follow-up seat, and this seat claims no

## 5. Common cause and severity

The r102 finding stands, one layer up: **the gate validates the artifacts it knows how to enumerate,
and nothing validates the gate's relationship to the documents that declare what it should be
enumerating.** Classes A, C, D, G and H all reduce to "the prose and the checker were never
compared"; class E to "the count is printed, not asserted"; class F to "the label is parsed, the
claim is not".

Severity ranking, for the close-out gate under adversary seats **[I]**:
1. **H** — highest, because the fix is documented as landed and is not: a reviewer reading
   `gate/README.md:31` believes the hole is closed.
2. **A** — the re-vendor's central claim (this tree *is* upstream at pin X) is unchecked end to end.
3. **C/D** — the two artifacts a reviewer uses to re-verify the pin can be corrupted freely.
4. **E/F/G** — narrower blast radius, same cause.
