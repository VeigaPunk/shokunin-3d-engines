## Verdict

**The F5 observation is true as an environment fact and false as a defect attribution.**
The command is correct and cwd-independent; it fails on a clean checkout only because a
gitignored, undeclared-by-the-cell *install precondition* has not been met. `engines.md:11` is a
**host-tooling census row**, not a lesson/receipt, and its *Notes* cell already states the
install precondition. The defect is therefore **not in the cited command and not in the fact
claimed** — the residual, genuinely defective part is narrower and different from what F5 says:

1. **Real sub-defect (P1, token-level):** the quoted result token `3/3` is printed by *both* the
   PASS and the FAIL summary line, so the quoted evidence string cannot discriminate success
   from failure. That is a citation-strength defect, independent of installs.
2. **Real sub-defect (P2, pointer-level):** the *Evidence* cell cites the bare command with no
   working directory and no install step, while the *Notes* cell holds the precondition — the
   two halves of the row disagree about what a reader must do.
3. **Adjacent defect (P3, discovered here, different file):** `corpus/fixtures/three/README.md:6`
   — the fixture's own declared install line — uses a dead path root and **exits 1**. This is a
   mechanical path-conformance defect of the F1 class and is arguably the *cause* a reader
   lands in F5's situation. It is **not** in F5's scope and is not in this seat's ownership.

F5's own verdict sentence ("the weakest of the six findings (the claim *is* true once installed)")
is consistent with this: the underlying engine claim is sound; only its citation is weak.

## 2. Why this is not a corpus defect (environment-fact argument)

1. **The row is a census, not a receipt.** `engines.md` is headed "Standing host reality (mint,
   2026-10-13) … every claim cites its probe". A census row is a statement about *this host's
   provisioned tooling*, not a promise that an unprovisioned clone reproduces it. The r6 design
   deliberately made `three` a **lane-local declared development dependency** with the generated
   `node_modules` ignored — recorded in `LOG.md:88-90` ("generated `node_modules` ignored",
   "scoped npm install is explicitly declared"). A gitignored install artifact is by
   construction absent from a clone; that is the intended shape, not an accident.
2. **The row already declares the precondition.** *Notes*: "`require.resolve('three')` failed
   from repo root before scoped install; no rendering, pixels or browser claim". The author
   disclosed the install requirement at write time. F5 concedes this and then files the defect
   anyway.
3. **`node_modules` presence here is not a special advantage of the reviewer's shell.** It is the
   normal state of any tree where the fixture has ever been run — including every seat in this
   round that ran `npm ci`. F5's own disclosure block (`r101-critic-c3.md:491`) admits the
   reviewer *created* `node_modules` itself with `npm install` mid-review, then treated the
   pre-existing state as the anomaly. The "clean tree" in F5 is a state the lane does not
   normally occupy; the "dirty tree" is the provisioned state the census describes.
4. **The claim survives provisioning; the pointer does not.** After `npm ci` the claim reproduces
   exactly (3/3, exits 0/2/1, seeds unchanged). A defect that a documented one-line install
   removes is a *pointer/precondition* defect, not a false claim about the engine.

## 3. What *is* defective, precisely

### P1 — the quoted token cannot discriminate pass from fail

```sh
$ node -e "
const ok='PASS three battery: 3/3, seeds_unchanged=true';
const bad='FAIL three battery: 3/3, seeds_unchanged=true';
console.log('cited token \"3/3\" in PASS?', ok.includes('3/3'));
console.log('cited token \"3/3\" in FAIL?', bad.includes('3/3'));
console.log('leading token differs:', ok.split(' ')[0], 'vs', bad.split(' ')[0]);
"
cited token "3/3" in PASS? true
cited token "3/3" in FAIL? true
leading token differs: PASS vs FAIL
```

`3/3` is a *case count*, printed identically on the failing run (see §1 BEFORE output, whose
last line also reads `FAIL three battery: 3/3, seeds_unchanged=true`). Only the leading `PASS` /
`FAIL` token changes. An evidence cell quoting `→ 3/3` therefore quotes the one number that
does not move. **This is the only part of F5 that is a genuine defect in the row, and it holds
whether or not the tree is provisioned.** It is a two-token fix: quote `PASS … seeds_unchanged=true`
or quote the exit code.

### P2 — Evidence cell omits the precondition the Notes cell states

The *Evidence* cell is the copyable one; it gives no working directory and no install step. The
precondition lives one column to the right. Minimum honest treatment is to make the copyable
cell self-sufficient (see §4, option A).

### P3 — adjacent, out of scope, discovered while testing (different file)

`corpus/fixtures/three/README.md:6` is the fixture's own declared install line and it is broken
by the dead `.shokunin/game-dev-3d/` root (the F1 root cause):

```
$ cd /tmp/f5clean2 && npm ci --prefix .shokunin/game-dev-3d/corpus/fixtures/three ; echo "exit=$?"
npm error code EUSAGE
npm error The `npm ci` command can only install with an existing package-lock.json or
npm error npm-shrinkwrap.json with lockfileVersion >= 1. …
exit=1
```

The correct repo-root form works (exit 0, §1). So the README's *declared* recovery path fails
while the *undeclared* one succeeds — which is the most likely reason a reader following the
documentation ends up with F5's `exit=1`. **This file is not owned by this seat and is not part
of F5's claim**; it is reported here as a routed finding for the repair owner. Note it is a
mechanical path-conformance fix (F1 class), not a historical factual claim, so the
correction-note discipline does not apply to it; but the *install command shape*
(`npm ci --prefix <dir>` from repo root) is a deliberate r6-era convention, so the owner should
confirm intent before rewriting all four README lines.

## 4. Minimal honest treatment — recommendation

F5 asks for a choice between "conditional note" and "command fix". Both, scoped narrowly; and
**do not** choose the two tempting wrong options.

**Recommended (A+B), both inside the existing cell, no new files:**

- **A (command/precondition fix, P2).** Make the Evidence cell's command self-sufficient at the
  same level of detail as the README already uses, e.g.
  `npm ci --prefix corpus/fixtures/three && node corpus/fixtures/three/run_cases.mjs` → `PASS … 3/3, seeds_unchanged=true`.
  The README is already the normative form; the cell should not be weaker than the fixture's own
  documentation. Alternatively keep the one-liner and put the precondition inline:
  `(after npm ci --prefix corpus/fixtures/three) node …`.
- **B (token fix, P1).** Replace the quoted result `→ 3/3` with the discriminating line
  `→ PASS three battery: 3/3, seeds_unchanged=true` (or with `exit=0`). Without B the cell stays
  un-falsifiable from its own quoted string, which is the substantive half of F5.

**Rejected: unconditional command fix.** Dropping the install step or the caveat would assert
clean-clone reproducibility of a gitignored artifact — a false claim, and a regression of the r6
"generated `node_modules` ignored" decision (`LOG.md:88`).

**Rejected: bare conditional note only.** A note like "requires `npm ci` first" fixes P2 but
leaves P1: the reader still cannot tell from the quoted `3/3` whether their run passed. It also
leaves the census row weaker than the README it summarizes.

**Rejected: vendoring `node_modules` (commit the 23M / 1264-file tree).** This would make the
bare command literally true on a clean clone, but it reverses the explicit r6 isolation decision,
adds a large untracked-content-shaped blob to the repo, and would re-contaminate the Godot seed
enumeration that r6 deliberately excluded (`LOG.md:90`). Not minimal, not honest about the
dependency, and it would create a new calibration hazard. Do not do this.

**Also rejected: leaving `engines.md` untouched entirely.** Defensible on the "census row, already
noted" argument, but it preserves a cited token (`3/3`) that appears on failure. P1 is cheap and
strictly improves calibration.

**Ownership note for the L1:** the fix belongs to whoever owns `corpus/knowledge/engines.md` this
round (C1(c) is declared as an "Unreal-row evidence-class update" on that same file), not to this
adversary seat. P3 (`corpus/fixtures/three/README.md`) is a separate routed finding and should be
assigned explicitly or left open with this report as its before-state evidence.
