## 3. The discipline, by file and line

The question this seat was asked turns on the protocol text. Quoted verbatim.

**`~/.kimi-code/skills/shokunin/protocol/CORPUS.md:52-58`** — the load-bearing rule:

> - **Corrections are new entries, never rewrites.** Lanes own
>   `lessons/round-<N>.md`; the aggregator writes only
>   `lessons/round-<N>-aggregator-*.md` and does not edit lane-authored corpus
>   files in place (same append-only discipline `PROTOCOL.md` gives `LOG.md`).

**`~/.kimi-code/skills/shokunin/protocol/PROTOCOL.md:123-125`:**

> Corrections land as new commits, never by amending a cited one (amending or rewriting orphans the
> record); append-only files (`LOG.md`) take an appended correction entry pointing at the superseded
> text, never an in-place rewrite.

**`PROTOCOL.md:348-351`:**

> - **Corrections sweep every mention.** Before a round's commit, grep every file the lane touches
>   (`corpus/README.md`, `SKILL.md`, `knowledge/`) for the superseded claim — a corrected fact left
>   standing in a sibling file is still a defect.
> - **A falsified claim in an append-only file gets a named correction entry in the lane's next
>   round** — appended, never rewritten; it stays on the routed-defect queue until it lands.

**`PROTOCOL.md:341-343`** — the clause that gives F1 its *only* real force:

> An evidence pointer must resolve at *closure* time, not only at write time: paths under `tmpfs`
> (`/tmp`, `/dev/shm`), session-scoped `local://` artifacts, and any pointer a fresh session cannot
> reach are not evidence — commit the artifact or cite a reproducible command.

**`PROTOCOL.md:447`:**

> - `LOG.md` is append-only: entries are never rewritten or deleted; corrections land as new entries.

**`PROTOCOL.md:415`** — the one carve-out for in-place correction of a *declared surface*:

> | `PROVINCE.md` | ... when a lane finds a surface moved or absent it corrects `PROVINCE.md` to the real path and logs the correction |

Note the asymmetry the protocol itself draws: an **in-place** correction is
sanctioned only for a *declared surface* (`PROVINCE.md`), and even then the
correction must be *logged*. Lessons get **appended** corrections. `PROVINCE.md:415`
therefore does not license an in-place rewrite of a lesson; it licenses the
opposite inference — in-place is the exception, granted narrowly.

## 4. Evidence on both sides

### 4a. The case FOR in-place repair (the repair seat's implicit position)

1. **The command genuinely fails from the repo root.** Re-derived here: `exit=2`
   (§1d). A reader who clones *this* repo and copy-pastes the command gets a
   traceback. `PROTOCOL.md:341` says a pointer must resolve at closure time; from
   the lane repo it never has and never will.
2. **There is a mechanical-fix precedent in this very round.** `reports/round-102/repairs/F1a-r22-readme.md`
   (SEAT-07) repaired `corpus/artifacts/unreal-r22/README.md:8-9` **in place**,
   reasoning: *"mechanical command/path conformance fix, applied in place (not a
   historical factual claim, so no dated correction note is required)."* That
   README now runs green (before `exit=2` → after `exit=0`, both captured in the
   F1a note).
3. **A note alone leaves a broken command.** If the only remedy is an appended
   note, the literal shell line still fails for every future reader; the note must
   then be read *before* the command is trusted, which inverts the usual flow.
4. **The failure mode is unambiguous and local.** The correct string is
   mechanically derivable by deleting one prefix; there is no interpretive
   judgement, no claim is contradicted, no number changes.

### 4b. The case AGAINST in-place repair (this seat's position)

1. **The claim was TRUE in its execution context.** §1 proves `.shokunin/game-dev-3d/`
   was a real tree at r22's write time, and the cited commands run `exit=0` from
   that worktree *today*. This is not a falsified claim like F2 (an absent receipt)
   or F3 (a stale SHA). Rewriting it in place does not correct an error — it
   **edits a true record into a different true record**, which is precisely what
   `PROTOCOL.md:123` ("rewriting orphans the record") and `CORPUS.md:52`
   ("never rewrites") forbid.
2. **Line 7 is narrative, not a command.** The r22 lesson line 7 reads:

   > I checked `.shokunin/game-dev-3d/LOG.md` round 22, `PROVINCE.md`, and `corpus/artifacts/unreal-r22/README.md`.

   This is a first-person **statement of what the author did**. `CORPUS.md:52`
   protects `lessons/round-<N>.md` by name. Changing "I checked
   `.shokunin/game-dev-3d/LOG.md`" to "I checked `LOG.md`" makes the lesson assert
   the author consulted a path that did not exist for them — **it introduces a
   false claim in order to remove a stale one**. That is the strongest single
   argument against the in-place route.
3. **The sweep clause makes a one-file fix incoherent.** `PROTOCOL.md:348`
   requires sweeping every mention before the round's commit. With **142 tracked
   files** (83 lessons) citing the prefix, an in-place fix of r22 alone satisfies
   neither the letter (siblings still stand) nor the spirit (the prefix remains
   the corpus's dominant convention). Either sweep all 142 — including
   `PROVINCE.md`, a governance file this lane may not casually rewrite — or don't
   claim the defect is closed.
4. **The F1a precedent is not transferable.** F1a repaired an *artifact README's
   runnable block*, whose whole purpose is copy-paste execution, and left the
   lesson untouched, explicitly deferring: *"The same stale path root also appears
   in `corpus/lessons/r22-unreal-review.md` ... left for the seat that owns the F1b
   lesson repair."* The artifact-README vs. committed-lesson distinction is real
   and is the distinction this ruling turns on.
5. **The protocol's own in-place carve-out is scoped to `PROVINCE.md`.** §3.
   A lesson is not a declared surface.
6. **No in-place-amendment precedent exists in this corpus.** Exhaustive search:

   ```
   $ grep -rn "^## Correction\|^## Erratum\|^> Correction\|Correction note" corpus/lessons/*.md
   (no output)
   $ grep -rl "2026-10-18" corpus/lessons/*.md
   (no output)
   ```

   Zero lessons carry a correction note; zero were written this round. The lane has
   never amended a lesson in place.

### 4c. Adjudication of the two sides

The FOR case is strong on **mechanics** and wrong on **record-keeping**. Its four
points all concern the *string*; the discipline concerns the *record*. F1a is
right that a *command block* is a mechanical surface. But the r22 lesson contains
**three different kinds of text** wearing the same prefix, and they must not be
treated alike:

| class | r22 lesson location | nature | correct disposition |
|---|---|---|---|
| A. narrative/historical | line 7 ("I checked ...") | first-person record of author's actions | **correction-note** (append); in-place rewrite forbidden by `CORPUS.md:52` |
| B. runnable command block | lines 23, 25, 29, 42, 44 | copy-paste reproduction recipe | **in-place permitted** *if* marked as a path-conformance fix, and only with the sweep ruled |
| C. bare prose path | line 48 (`node .shokunin/.../scene_graph.mjs`) | mixed narrative + command | **correction-note**; falls with A |

The routed F1 as filed does not make this distinction, which is why it produced a
mis-framed repair.

## 5. RULING

**R1 — F1 is real but mis-routed; the r101 premise "that root has never existed"
is REFUTED for the context in which r22 was written.** Evidence §1. The path was a
real tracked tree (git mode `040000`) that became a symlink (`120000`) at
`e1e863c3`, ~14.5 h *after* r22 landed. The r101 check (`r101-critic-c3.md:146`)
is a correct observation about *this* repository, generalised into a false
universal. It must be re-filed with its scope stated: **"the prefix does not
resolve from the lane repo root"**, not **"the root never existed."**

**R2 — The in-place rewrite of the r22 lesson's narrative is FORBIDDEN.**
Recommendation: **correction-note**. Line 7 (class A) is a committed historical
record; `CORPUS.md:52` ("Lanes own `lessons/round-<N>.md` ... never rewrites") and
`PROTOCOL.md:123` ("never an in-place rewrite") bind it. Rewriting it would replace
a context-true citation with a claim that misrepresents what the author did.

**R3 — A bounded in-place fix is permitted ONLY for the class-B command block
(lines 23, 25, 29, 42, 44), and is DEFERRED.** `PROTOCOL.md:341` is the clause that
justifies it (a pointer must resolve at closure from a fresh session). But
`PROTOCOL.md:348`'s sweep duty is unsatisfiable at r22-only scope: 142 files cite
the prefix, `PROVINCE.md:46` among them. **Do not repair r22's commands in place
until the L1 rules the systemic question.** A one-file fix that leaves 141 siblings
— and the lane's own write-scope declaration — still carrying the prefix converts a
routed defect into a standing conformance defect.

**R4 — The systemic scope must be ruled by the L1, not by a seat.** Options, in
this seat's order of preference:
1. **Single appended correction note** in `corpus/README.md` (the index) stating
   that the lane's historical lessons cite paths through the
   `.shokunin/<lane>/` worktree convention declared by the fleet wave spec, that
   this convention does not resolve from the lane repo root, and that the
   repo-root-relative form is the executable one. One note, one sweep, no history
   edited. Satisfies `PROTOCOL.md:348` and `CORPUS.md:52` simultaneously.
2. **Correction note in `corpus/README.md` + bounded in-place fix of the class-B
   command blocks only** across the affected files, each commit message naming the
   path-conformance basis (the F1a precedent, applied at declared scope).
3. **Full in-place sweep of all 142 files.** Rejected by this seat: it rewrites
   history across the corpus, touches `PROVINCE.md`, and is the largest-blast-radius
   option for the smallest reproducibility gain.

**R5 — The repair currently in the working tree is NON-CONFORMANT and must be
flagged.** `git status --porcelain` shows `corpus/lessons/r22-unreal-review.md`
modified, and the diff **silently rewrites line 7**:

```
$ git diff -- corpus/lessons/r22-unreal-review.md | grep -c "^[-+].*shokunin/game-dev-3d"
7
```

with, verbatim from the diff:

```
-I checked `.shokunin/game-dev-3d/LOG.md` round 22, `PROVINCE.md`, and `corpus/artifacts/unreal-r22/README.md`.
+I checked `LOG.md` round 22, `PROVINCE.md`, and `corpus/artifacts/unreal-r22/README.md`.
```

That is an in-place rewrite of a historical narrative with **no dated correction
note**, against `CORPUS.md:52` and `PROTOCOL.md:123`. The lesson is not this
seat's to edit (write scope: this file only), so this is reported, not reverted.
**This seat recommends the L1 either (a) direct the owning seat to restore line 7
and carry the change as an appended correction note, or (b) explicitly rule that
class-B command lines may be fixed in place while line 7 is restored verbatim.**

**R6 — No Unreal runtime claim is made or implied anywhere in this ruling.** The
r22 artifacts are static-only; Unreal Editor is not installed on this host, and the
`exit=0` runs captured in §1d exercise a local JSON checker, not an engine.
