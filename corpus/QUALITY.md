# QUALITY — admission bar for game-dev-3d corpus/knowledge

This bar governs admission of `corpus/knowledge/` entries and round claims.
Source tiers are defined in `corpus/SOURCES.md` under frozen contract v1; this file does not redefine them.
Research follows chousa's method in `chousa-shokunin/SKILL.md`; consult it rather than duplicating it here.
Apply every criterion relevant to the proposed entry or claim before admission.

## Criteria

| id | criterion | lesson | check |
|---|---|---|---|
| Q1 | The admission bar is present and applied to every new knowledge entry and round claim; a missing or unapplied bar blocks admission. | `corpus/lessons/round-108.md` M14 | Run `test -f corpus/QUALITY.md`; then record the pass or explicit failure for each applicable Q criterion in the entry's round lesson. |
| Q2 | Each knowledge entry opens with `source:` naming its `S###` row, URL, and anchor; `verified-at:` is an ISO date; `recheck:` gives a date or cadence plus a command or source. | `corpus/lessons/round-108.md` M14 | For each proposed entry, inspect its opening metadata, resolve the named S row in `corpus/SOURCES.md`, check URL and anchor, parse the date, and confirm the recheck names both cadence and a reproducible command or source. |
| Q3 | Support meets the source-tier minimum: at least one tier-A row or two independent tier-B rows whose scope covers the claim; tier-C is never sole support. | `corpus/lessons/round-108.md` M14 | Trace every cited claim to its S rows, confirm each row's declared tier and scope, and count independent tier-B origins rather than URLs alone. |
| Q4 | Every claim is falsifiable and scoped to engine and version, backend or renderer, and settings; state a dimension as not applicable when it truly does not apply. Re-derive every numeric claim from its source rows and stated frame. | `corpus/lessons/round-108.md` M19, M4 | For each claim, write its observable falsifier and context; independently recompute each number from the cited raw rows with the stated command and frame. |
| Q5 | Document facts and observed runtime behavior are separate propositions; documentation, static inspection, and source code do not establish runtime behavior. | `corpus/lessons/r12-import-review.md:17-21` | Mark each proposition as document/static or runtime; split any sentence that uses one as proof of the other and check its evidence accordingly. |
| Q6 | A runtime claim has a saved, bounded receipt satisfying `SKILL.md` §1 row F: exact command and scope, aggregate and named-row verdicts, exit and reasons, `seeds_unchanged=true`, and named non-author replay. | `corpus/lessons/r105-unreal-lifecycle.md:7-8` | Open the receipt and run the row-F checklist in `SKILL.md` §1 F against the exact command, target, environment, timeout, seed digests, and non-author replay. |
| Q7 | A `--headless` run is not evidence of rendered pixels or visual output. | `corpus/lessons/r12-import-review.md:19,29` | Inspect the command and receipt; reject any visual claim supported only by a headless run, or attach a separate bounded rendered-output receipt. |
| Q8 | A REJECT, failed control, or dead author seat stays adverse or unverified until a named non-author replay and explicit adjudication address the counterexample; preserve the adverse record. | `corpus/lessons/round-108.md` M1, M2 | Compare the verifier's named counterexample with the repair bytes and receipt; require an independent replay and a recorded adjudication before changing the verdict. |
| Q9 | A verifier or falsification result names the exact target SHA-256; gate admission also includes an adversary suite whose expected detections run against those same bytes. | `corpus/lessons/round-108.md` M7, M8 | Hash the target with `sha256sum`, record that hash in the verdict, run every declared adversary against that revision, and confirm each expected detection. |
| Q10 | Physics fixtures sample at an engine iteration boundary after a fixed number of settled ticks, never inside a physics callback. | `corpus/lessons/round-108.md` M3 | Inspect the fixture's sampling site and tick counter; confirm the assertion is emitted only after the declared iteration boundary and settled-tick count. |
| Q11 | Contention- or load-sensitive cells declare their load envelope and are measured under it; unstable wall-clock or load-dependent results are not pinned as universal constants. | `corpus/lessons/round-108.md` M4, M6 | Repeat the cell under its declared load class, capture the observed range and repeat count, and check that any exact pin is stable within that envelope. |
| Q12 | Child output is drained deterministically through teardown; partial-line output is never treated as a stable pinned value. | `corpus/lessons/round-108.md` M5 | Exercise child shutdown with a final partial line and verify the saved receipt contains complete, attributed streams before classifying the result. |
| Q13 | Battery inputs run from a write-isolated snapshot with before/after seed digests; concurrent seed mutation is infrastructure failure, not a row verdict. | `corpus/lessons/round-108.md` M11, M16 | Compare the snapshot's seed manifest before and after execution; confirm the run cannot share writable seed paths with another author or verifier. |
| Q14 | Before execution, declare the actual lane root and exact per-path write scope, distinguish fixture code from fixture docs, and use a writable scratch root that exists; do not assume shared `/tmp` quota. | `corpus/lessons/round-108.md` M9, M13, M18, M22 | From the lane root run `git rev-parse --show-toplevel`; check each declared path exists or is explicitly a new target, verify writes remain inside scope, and probe the selected scratch root for writable quota. |
| Q15 | Documentation for an override or command matches the implementation and reproduces its stated result from the stated working directory. | `corpus/lessons/round-108.md` M10 | Search the implementation for the documented option, run the exact documented command from its stated directory, and compare its real output and exit code with the prose. |
| Q16 | Verdict dates are not later than the declared round date; no placeholder remains; each `Work` reference names the exact landed work commit and is an ancestor of its report-last commit. | `corpus/lessons/round-108.md` M17, M20, M21 | Parse every ISO date against the round date, search the verdict for `<WORK>` and other unfilled fields, inspect commits with `git show`, and check ancestry with `git merge-base --is-ancestor <work> <report-last>`. |
| Q17 | Counts in prose are measurements, not constants: enumerate the registered rows and saved receipt rows at close, then update all affected documentation. | `corpus/lessons/round-108.md` M15 | Run `grep -cE '^\s+\("' corpus/fixtures/run_battery.py`; compare it with the saved receipt's result count and the counts printed in affected documentation. |
| Q18 | Provider exhaustion closes only the verified subset, names the exhausted provider and remaining work, and never treats automatic retries as completed seats. | `corpus/lessons/round-108.md` M12 | Reconcile provider usage and retry records with independently verified artifacts; list the verified subset and route every unfinished item explicitly. |

## Using this bar

An entry lands only if every applicable Q criterion passes and its evidence pointers resolve.
Record each pass or failure explicitly; do not waive a failed criterion silently.
Record the exact pass list in the entry's round lesson under `## Gate`.
Recheck when a cited source changes and at the entry's stated `recheck:` cadence.
