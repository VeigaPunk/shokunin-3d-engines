## Three lessons / gains from this window

1. **S034 cites a Jolt version the r108 measurements never ran on.** Yesterday's report left open which Jolt revision Godot 4.7.2 bundles. I checked `thirdparty/README.md` at three refs:
   - `4.7.2-stable` (what r108 measured with): Jolt **5.5.0** (`23dadd0e`).
   - Godot `4.8-beta4` (godot-builds release 2026-11-18, commit `b070e63b`): Jolt **5.6.0** (`e77f1755`).
   - Godot `master`: also 5.6.0 (`e77f1755`).

   S034 (`corpus/SOURCES.md:42`) cites the v5.6.0 release notes at tag commit `e77f1755`. That's exactly the 4.8 bundle, one minor version *ahead* of the engine behind S035 (the 45.57–45.58° floor/wall flip under Jolt, `boundary-scan.txt`). So the v5.6.0 "stuck character in steep-slope enclosures" fix S034 points to is **not** in the measured 4.7.2 build. S034's own guidance says to "pin physics release when testing character slopes", but neither row records the bundled Jolt version. This corrects yesterday's framing: Jolt v5.7.0 is two releases past the measured engine, not one.

2. **Godot 4.8 is in beta and will flip the "stable" docs rows without warning.** `godot-builds` has published `4.8-beta1` (2026-10-15) through `4.8-beta4` (2026-11-18, inside this window). The main `godotengine/godot` repo carries only `-stable` tags, so a check that only looks at `releases/latest` (what I did yesterday) sees "4.7.2" and misses that a minor bump is close. When 4.8-stable ships, two things change at once: the 9 `docs.godotengine.org/en/stable/` rows (S001–S009, S011, S012) start serving 4.8 content under a "stable docs 4.7" anchor, and the bundled Jolt moves 5.5.0 → 5.6.0 under the Jolt-project batteries. A re-run of the r108 slope/boundary battery on 4.8 then wouldn't be comparable to r108 unless the backend version is recorded. Other upstreams are unchanged since yesterday: Jolt v5.7.0, Bevy v0.20.1, three.js r187.

3. **three.js baseline held for a 5th day, and the obvious version probe is broken.** Cold-start `npm ci` of `corpus/fixtures/three` (three `0.186.1`, Node v24.22.1) passed **41/41** again: box3 5, camera 5, cases 3, layer 4, lookat 5, order 9, ortho 5, ray 5, plus `scene_graph.mjs` PASS. All exited 0 with the same counts as 11-17 through 11-20. Side note: `require('three/package.json')` throws `ERR_PACKAGE_PATH_NOT_EXPORTED` because three's `exports` map hides it. Any env-preflight or manifest that wants the installed version has to read `package-lock.json` or `node_modules/three/package.json` directly, not resolve it through the module system. That matters for the `node=v24.21.0` env-preflight ask that's still parked.
