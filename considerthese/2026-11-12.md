## Three lessons / gains from this window

Nothing new landed, so these come from parts of the tree earlier reports hadn't examined.

1. **"3D engines" means runtime evidence for Godot and the web stack, and only static evidence for Unity and Unreal.** `corpus/artifacts/unity-r19/README.md` says the scene is self-authored and "has **not** been imported or validated by Unity Editor". `corpus/artifacts/unreal-r22/README.md` says the `.uplugin` "was not loaded by Unreal Editor or UnrealBuildTool". Every runtime row in `corpus/fixtures/run_battery.py` comes from Godot (GodotPhysics, Jolt, Dummy), three.js 0.186.1, cannon-es 0.20.0, pybullet, or Blender 5.2.1. That is honest scoping, since QUALITY Q5 keeps document/static claims apart from runtime ones. But the lane name promises more breadth than its evidence covers. Unity and Unreal knowledge should be read as tier "document/static" until an engine actually runs them.

2. **`corpus/QUALITY.md` makes the lane checkable against its own rules, and two of them fail on `main` today.** Q15 says documented commands must reproduce "from the stated working directory". The 3 `SCORECARD.md` commands that use the `.shokunin/game-dev-3d/` prefix fail that test from repo root. Q17 says counts are measurements and gives a command: `grep -cE '^\s+\("' corpus/fixtures/run_battery.py`. On current `main` that returns **355**, while `corpus/fixtures/PINNED-ENV.md` explains its r104 result as 337/**350**. I haven't checked whether the 5-row gap is real added cases or just tuples the grep over-counts. Either way, the lane's own bar says that prose count needs re-measuring.

3. **Vendored three.js matches the npm pin, but the pybullet vendor copy is tied to one ABI.** `corpus/fixtures/r94vendor/three.core.js` declares `REVISION = '186'`, and `corpus/fixtures/three/package-lock.json` resolves `three` 0.186.1. So the cannon-es battery (`r94_cannon`) and the standalone three.js runners exercise the same three.js release. That's a real consistency gain worth keeping. On the other hand, `corpus/fixtures/r95vendor/pybullet.cpython-314-x86_64-linux-gnu.so` is a compiled binary for CPython 3.14 on x86_64 Linux only. Together with the host-absolute node path in `PINNED-ENV.md`, it's a second way the battery is bound to one machine.

New since earlier reports:

1. **Run the API-checkable QUALITY criteria every day.** Q15 (documented paths exist), Q16 (no placeholders, dates not after round date), and Q17 (row count vs prose counts) can each be checked read-only from GitHub. I'd report them as a small pass/fail line instead of finding them one at a time, as in item 2.
2. **Engine × evidence-tier matrix.** Keep a short table: one row per engine (Godot/GodotPhysics/Jolt, three.js, cannon-es, pybullet, Blender, Unity, Unreal), and columns doc / static / runtime-receipt. Then coverage gains and gaps (like item 1) show up as cell changes rather than prose.
3. **Vendored-dependency ledger.** List each vendored library with its declared version, blob SHA, and ABI or platform tag. Flag any mismatch against lockfiles, and any binary that only loads on one interpreter or architecture.
4. **Compress quiet days.** After 7 quiet days in a row, switch to a shorter file (window line, any corrections, open asks) until something lands, so the reflections don't drown out real lane changes.
